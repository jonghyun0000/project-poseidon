# Phase 22 — 항로 바람·도착 제약·제공 연료 곡선

2026-09-12 KST. 사용자 요청: 다음 단계를 찾아 실행한다.

## 판단과 구현 범위

Phase 21의 항로 환경 분석에 **실제 GFS 바람, 도착 마감, 출처를 명시한 선박 연료 곡선**을 연결했다.
현재 로컬 저장소에는 파랑 예보와 같은 사이클의 GFS u10/v10이 있지만 대상 상선의
실측 성능표와 해류 자료는 없다. 따라서 실제 선박의 기상 감속이나 연료 절감을 만들어 내지 않는다.
파랑 물리 엔진의 `uno2/none` 동결은 유지했다.

[ITTC 7.5-02-07-02.8, 2024 rev.2](https://ittc.info/media/11900/75-02-07-028.pdf)는
정온 저항과 바람·파랑 추가 저항, 추진 성능을 함께 다룬다. 이 자료가 없는 상태에서
임의의 파고 감속률이나 속력 세제곱 법칙을 실선 예측으로 채택하는 안은 제외했다.
이번 기능은 검증된 기상 연료 모델이나 최적 항로 엔진이 아니다.

## 계산 계약

- API: `POST /v1/voyage/analyze`, 응답 `schema_version=voyage-1.1`. 기존 요청은 그대로 가능하다.
- 바람: 파랑과 **동일 사이클**의 `noaa-gfs-0p25`만 사용한다. 다른 사이클로 대체하지 않는다.
  대기 u/v를 공간 쌍선형·시간 선형 보간한 뒤 풍속과 오는 방향을 유도한다.
  풍향 각도를 직접 평균하지 않는다. 대기는 육지 위에도 있으므로 해양 마스크를 적용하지 않는다.
  예보 시각·도메인 밖, 비유한 값, 자료 읽기 실패는 상태와 null로 반환한다.
- 이동 상대풍: 지구 기준 10 m 바람 벡터에서 일정 SOG/COG의 선박 이동 벡터를 뺀다.
  1 kn = 1852/3600 m/s. 무풍 또는 상대풍 0의 방향은 null이다.
  갑판 높이, 돌풍, 풍저항, 선박의 선수방위·횡동요는 반영하지 않는다.
- 바람 커버리지: 양 끝의 바람이 유효한 구간의 시간을 합산한다. 지점 개수 비율이 아니다.
  최대 풍속은 조회 지점의 최대이며 연속 시공간 극값 또는 돌풍이 아니다.
- 도착 마감: `arrival_deadline_utc`는 시간대가 있는 선택 입력이다. 마감−일정 SOG ETA를
  시간 단위로 표시한다. 0 이상은 `on_time`, 음수는 `late`, 육지 통과는 판정 제외다.
- 연료: `performance_profile`은 기본 null. 이름, 자료 구분, 출처, 적재·흘수 조건,
  단일 연료 종류, 대수속력(STW)–총 해상 연료(t/day) 표와 명시적인 무해류 동의가 필요하다.
  2–20행, 속력 1–40 kn, 양의 연료율, 속력 중복 없는 오름차순을 검증한다.
  제공 구간 안에서만 선형 보간하고 외삽하지 않는다. SOG=STW는 무해류 가정에서만 적용한다.
- 연료 총량 = 제공 곡선의 t/day × 해상 항해 시간 / 24.
  바람·파랑 저항, 출항 전 대기, 항내 연료를 제외한다. 같은 속력의 6시간 지연 출항은
  이 범위에서 연료가 같으며 전체 운항의 경제성이 같다는 뜻은 아니다.
- 연소 CO₂ = 연료 t × CF. HFO 3.114, LFO 3.151, Diesel/Gas oil 3.206 t-CO₂/t-fuel.
  출처: [IMO MEPC.364(79), §2.2.1 (2022)](https://wwwcdn.imo.org/localresources/en/KnowledgeCentre/IndexofIMOResolutions/MEPCDocuments/MEPC.364%2879%29.pdf).
  전 과정 온실가스, CII, EEDI 또는 EEOI 인증 결과가 아니다.
- `source_kind`는 제공자 기재이며 검증 이력이 아니다. 응답에 `source_verification=user_declared_not_verified`를 남긴다.
  `synthetic_example`은 UI·JSON·CSV에서 가상 예제로 표시한다. 실선 검증 또는 절감 근거가 아니다.

## 화면과 재현 파일

`/console?view=voyage`: 10 m 풍속·이동 상대풍, 시나리오별 최대 풍속/커버리지,
마감 여유·초과 시간, 선택형 성능표 입력과 연료·연소 CO₂ 기준값을 추가했다.
입력 변경 시 이전 결과의 재생·내보내기를 막는다. JSON 입력 복원도 새 성능표와 마감을 복원한다.
JSON은 입력/방법/원천/시나리오를 담고 CSV는 바람과 연료 출처·계산 범위를 보존한다.
CSV의 `fuel_t_total`, `combustion_co2_t_total`은 **시나리오 총량을 각 지점 행에 반복**하므로 합산하면 안 된다.

실제 과거 환경 예제 (선박 성능표 미입력):

- 요청: `docs/api/voyage-environment-request.example.json`
- 결과: `reports/voyage-environment-example.json`, `.csv`
- 사이클: `20260906T18`. GFS 유효기간: 2026-09-06 18:00–09-09 18:00 UTC.
- 항로 423.0731 nm, 마감 2026-09-08 04:00 UTC, 파고 비교선 3 m.

| 시나리오 | 항해 h | 최대 조회 풍속 m/s | 3 m 초과 h | 마감 여유 h |
|---|---:|---:|---:|---:|
| 기준 14 kn | 30.2195 | 15.5713 | 17.9469 | +3.7805 |
| 6시간 후 14 kn | 30.2195 | 14.8974 | 9.6391 | −2.2195 |
| 감속 12 kn | 35.2561 | 15.5042 | 19.6596 | −1.2561 |

각 시나리오 파랑·바람 시간 커버리지 100%, 87지점. 연료와 CO₂는 전부 null.
지연 출항은 이 예제에서 파고 초과 시간을 줄이지만 설정된 마감은 넘긴다.
일정 SOG와 과거 예보의 결과이며 현재의 출항 권고가 아니다.

별도 가상 기능 시험 자료:
`docs/api/voyage-synthetic-fuel-request.example.json`,
`reports/voyage-synthetic-fuel-example.json`, `.csv`.
가상 곡선 8/12/14/16 kn → 8/18/28/42 t/day를 사용했다.
14 kn 해상 연료 35.2561 t, 12 kn 26.4421 t는 **인위적인 입력의 산술 결과**다.
실선 성능이나 감속 절감률로 인용하면 안 된다. 최종 화면에서는 이 곡선을 해제했다.

## 검증과 운영

- 전체 Python: `.venv/bin/python -m pytest -q` → **309 passed**, 197.32 s.
  기존 scientific 91건을 포함한다. 경고 4건은 Starlette 전환/Zarr v3 메타데이터 경고다.
- Node: `node --experimental-default-type=module --test tests/web/*.mjs` → **12 passed**.
- 새 검증: 공간·시간 벡터 보간, 북쪽 풍향 경계, 정지/맞바람/뒷바람/상대풍 0,
  범위 밖·누락·NaN, 시간 가중 커버리지, 단위 환산, 연료 무입력·외삽 금지·출처,
  CF, UTC 동치/정시/지연, 잘못된 성능표 422, 바람 읽기 실패 때 파랑 유지.
- 실제 로컬 API 응답과 예제 파일을 대조했다. 이 검증은 계산·제품 계약의 검증이며 실선 정확도 검증이 아니다.
- 브라우저에서 실제 환경 분석 → 명시적 가상 곡선 시험 → 곡선 해제까지 확인했다.
  입력 변경 시 저장 비활성화, 1280×900 및 390×844 배치, 가로 넘침 없음, 콘솔 오류 없음.
  JSON/CSV 각각 261지점의 행 수와 출처·연료 결측을 확인했다.
- API launchd 서비스만 갱신했다. 기존 운영 PID 90164는 같은 프로세스로 계속 실행 중이다.
  최신 등록 파랑은 여전히 과거 사이클이며 화면에서 현재 예보처럼 표시하지 않는다.

## 다음 실무 게이트

1. 대상 선박의 정온 성능표, 적재·흘수, 추진/소모 자료와 독립 항차 실측 확보.
