## A. 측정 경로가 결과를 만든다

이 프로젝트에서 가장 많이 반복된 실패 계열이다. 공통점: **놀라운 결과든 안 나오는 결과든, 먼저 측정 도구를 의심한다.**

### A-1. 마스크·유효범위 미확인 — 7회

| # | 위치 | 결과 |
|---|---|---|
| 1 | `collocate.py` 관측소 보간이 육지 hs=0을 섞음 | "L2 천해 27% 개선" 허구, 보고까지 됨 |

1~4·6·7은 마스크, 5는 시간 범위다. **7번은 한 사이클에서 발견(PHASE18)하고 21일 뒤에야 원인을 확정했다** — 발견 즉시 '보간 결과 NaN 셀'과 대조했으면 몇 분이었다. 공통: **입력의 유효 범위를 검사하지 않고 계산을 진행했다.**
산출물을 재사용할 때는 존재 여부가 아니라 **요구 조건 충족 여부**를 확인한다.

규칙:
1. 해상도가 다른 모델을 관측과 비교하기 전에 관측소마다 `land_frac`을 기록하고, 오염 표본을 배제하거나 sea-normalized 보간을 쓴다
2. 놀라운 개선(>20%)은 물리 성과로 보고하기 전에 측정 경로부터 의심한다
3. **마스크 결함은 NumPy/JAX 동등성 게이트로 못 잡는다** — 두 백엔드가 같은 함수를 공유하면 똑같이 틀린다. 육지가 포함된 테스트 케이스를 반드시 둔다
4. 산출물을 갱신했으면 파생 지표(콜로케이션·학습·평가)를 전부 다시 만든다. 그럴 수 없으면 코드를 먼저 동결한다

**표시 경로에 아직 남아 있다** `[확인 필요 2026-09-11]`: `app.py field_hs_png`의 업스케일
`ndimage.zoom(np.where(sea, hs, 0.0), order=3)`이 육지 0을 연안 해상 셀로 번지게 한다(PHASE18 §9 10단계).

### A-2. 기준선이 내 입력이면 ΔRMSE는 독립 스킬이 아니다

PHASE12(2026-08-25): 자체 엔진이 GFS-Wave 대비 RMSE −17.3%였다. 그런데 GFS-Wave는
**초기 스펙트럼, 4면 경계 강제, 비교 기준선** 세 역할을 동시에 맡고 있었다.
리드 0 표본의 76.4%가 두 예보 간 비트 단위로 같았고, 두 예보 오차의 상관은 0.835였다.
공유 오차는 ΔRMSE에 나타나지 않는다. 우위의 65%는 평균 편향 차이였다.

규칙:
1. 기준선을 정할 때 먼저 묻는다 — "이 기준선이 내 시스템의 입력 경로에 들어가는가?"
2. 들어간다면 ΔRMSE 옆에 **오차 상관을 항상 병기**하고 "증분 검정"이라고 쓴다
3. 편차제거 RMSE를 함께 보고해 우위가 절편에서 오는지 산포에서 오는지 나눈다
4. 진짜 독립 검정은 어느 경로에도 안 들어간 제3의 관측이 필요하다 — 위성 고도계(NOAA LSA RADS 미러, 무인증 확인됨)가 후보

### A-3. 집계 방식이 결론을 바꾼다

PHASE17(2026-09-07): "계통적 과소 −0.043 m"는 **사이클별 중앙값**이었다. 표본 가중 전체 bias는
**−0.0029 m, 무의**(24사이클 3,984건, CI [−0.061, +0.053]). 사이클별 표본이 20~390건으로 달라
두 통계가 갈렸다. 그리고 진짜 구조는 리드 의존이었다 — 유의한 편향은 리드 0–6 h 과소 −0.163 m 하나뿐.

규칙: **집계 방식(표본 가중/사이클 중앙값)을 먼저 명시한다.** 두 값이 다르면 둘 다 쓴다.
부호가 다른 구간이 상쇄돼 전체가 0이 될 수 있으므로 층별(리드·파고대·해역)로 나눠 본다.

### A-4. 채점되지 않은 것을 "검증 불가"로 착각했다

PHASE12 §3.2(2026-08-27): 콜로케이션이 **사이클당 1회, 예보 직후에만** 돌아서 72 h 예보가 있어도
리드 3 h까지만 채점됐다. 10사이클 최대 69 h 미채점. 재콜로케이션으로 표본 2,301 → 3,652건, 리드 0 → 72 h.
**"48–72 h 검증 불가"는 표본 문제가 아니라 채점 누락이었다.**

규칙: 관측이 쌓인 뒤 기존 사이클을 **다시 콜로케이션**한다. "표본 없음"을 보면 먼저 채점 파이프라인이
그 조건을 채점하도록 짜여 있는지부터 본다.

## E. 파향 검증 — 단일 Hs 임계를 쓰지 않는다 (PHASE13 §9)

네 갈래 조사가 같은 결론에 도달했다.

- 관측 자기일관성: 저파고에서 매끄럽게 나빠지다 0.45~0.55 m에서 평탄해진다. **무릎이 없다**
- 모델 채점: 55건·1사이클에서 임계별 CMAE가 단조롭지 않고 모든 CI가 겹친다
- 문헌: **파향용 Hs 임계 표준이 없다.** Met Office AMM15·CMEMS는 필터 없이 검증한다. 통용되는 1 m에는 근거가 없다. 확증된 유일한 숫자는 NDBC Tech Doc T80-10 §6.2.11.3의 Hs<0.25 m 미발표
- 최종 용도: IMO MSC.1/Circ.1228 조건이 Hs > 0.04·L로 **선박 길이 함수**라 상수로 역산할 수 없다

채택: 파고대별 보고(`collocate.direction_skill`) + 임계 민감도 표(`threshold_scan`) + 계기 하한
Hs≥0.25 m(`INSTRUMENT_HS_MIN`, 성능 임계 아님, 데이터로도 유의). `scientific` 게이트에는 파향 성능이
아니라 **규약 회귀만** 둔다(`tests/scientific/test_direction_convention_gate.py`).

**보고 규칙**: 파향을 CMAE 평균 하나로 보고하지 않는다. 중앙값·within-45°·>90° 비율을 병기해야
꼬리와 본체가 구분된다. 임계를 올려 성적이 좋아 보이면 그건 표본을 고파고로 편향시킨 결과다.

관측 결함: KMA:22105·22191·22192가 젊은 풍성파 조건에서 파향이 풍향과 90° 넘게 어긋난다(52~92%).
`collocate.direction_sensor_check()`가 데이터로 검출한다(하드코딩 아님).

`dspr`을 보조 지표로 쓰는 안은 기각했다 — 절단값 24~30에서 효과가 −7.6~−24.3°로 요동(knife-edge).

## F. 엔진 지식 — 재사용 가치가 있는 것

- 방향을 회전시키는 소스항은 **Sin 하나**다(cos(θ−θw), 음의 입력 없음). 스웰 방향은 오직 이류로만 정해진다
- 평균파향 회전의 주역은 DIA가 아니라 **Sds(Komen)** 다(4.2배). DIA는 경상 대칭이라 회전이 상쇄되고 확산만 만든다 — 통념과 다르다. Sds는 θ 의존성이 없는데도 kr=k/k̃ 주파수 선택성 때문에 평균파향을 움직인다
- 고파고 파향 오차는 대부분 이류·초기장이 결정한다(순수 이류 A/B에서 소스항 기여 무의, 단 n=183·1사이클)
- **백파 소산을 약화시키는 방향으로 고치지 말 것** — 끄면 훨씬 나빠진다(PHASE12 §11-5)
- JAX/NumPy 이중 구현에서 소스항이 복제돼 있으면 한쪽 수정이 조용히 무시된다. `xp` 제네릭 공유 함수로 통합했다(PHASE16 — Wu 식 삼중 복제 제거)
- 실험 인프라: `run_wave_forecast(enable=..., drag=..., swell=...)`는 진단 전용이며 `out_tag` 없이 부르면 ValueError. 동결 구성을 명시하면 운영과 8변수 비트 동일 — **이 게이트를 먼저 통과시키고 A/B 한다**
- 동결 엔진 + 동일 강제장이면 hs가 격자 137,295셀 전부 비트 동일하다(백필 안전성 증명)

## G. 화면·실행 환경

### G-1. 숨김 탭에서는 지도가 조용히 멈춘다

브라우저 탭·패널이 숨김(`document.hidden === true`)이면 `requestAnimationFrame`이 발화하지 않는다.
MapLibre는 인라인 스타일도 첫 프레임을 rAF 위에서 처리하므로 `style.load`조차 끝나지 않는다.
`getStyle()`은 `undefined`, `isStyleLoaded()`는 영원히 false, **에러는 0건**이다.

2026-09-07에 이것을 앱 버그로 오진해 베이스맵 교체·강제 개방 타이머·재시도 루프·스타일 분리를 네 번
헛고쳤다. 그동안 타일도 `hs.png`도 API도 전부 200이었다.

규칙: 렌더가 안 보이면 코드를 만지기 전에 `document.hidden`과 rAF 발화를 확인한다.
헤드리스 검증이 필요하면 `window.requestAnimationFrame = cb => setTimeout(() => cb(performance.now()), 16)`
셈을 **maplibre 스크립트보다 먼저** 임시 삽입하고 확인 뒤 반드시 제거한다(사후 패치는 라이브러리가 rAF를 이미
잡아서 안 먹는다). 숨김 상태에서는 `getBoundingClientRect`·`innerHeight`도 0으로 나온다 — 레이아웃 계측도 무효다.
`scripts/ui_check.js`가 `hidden`을 먼저 보고한다.

### G-2. 성공 로그를 반영의 증거로 읽지 말 것

2026-09-07: 한 패치 스크립트가 단언 5개 중 앞의 2개에서 "ok"를 찍고 3번째에서 실패했다. 파일 쓰기는
맨 끝에 있었으므로 **앞의 2개도 저장되지 않았다.** "ok" 로그만 보고 반영됐다고 읽어 CSS 토큰 정의가
조용히 유실됐다. 결과물을 다시 읽어 확인한다.

### G-3. 일괄 치환은 정의 블록까지 먹는다

색 리터럴을 `var(--x)`로 올리는 일괄 치환이 야간 팔레트 정의 블록 **안쪽까지** 바꿔
`--fg: var(--fg)` 같은 자기참조를 만들었다. 야간 글자가 거의 안 보였다.
치환 뒤에는 자기참조·미정의 토큰을 검사한다.

### G-4. 물리적으로 정확하면 밋밋해 보인다

Tp 12.8 s 스웰은 파장:파고가 약 300:1이라 실제로 완만하다. 가파른 것은 짧은 풍파(Hs 5.66 m·Tp 7.6 s).
시각적 인상과 위험은 다르다. 종파에서 |sin α|=0이라 롤이 0으로 나와 '안전'으로 읽혔는데
바로 그 조건이 파라메트릭 롤 위험역이었다(PHASE14 — 방향확산 σ를 넣고 `parametric_risk`를 분리).

### G-5. launchd 아래에서는 외장 볼륨이 안 보일 수 있다

2026-09-22: 감시 스크립트를 zsh + `/usr/bin/sqlite3` 로 짰더니 대화형 셸에서는 멀쩡했는데 launchd 에서는
`Operation not permitted` / `authorization denied` 로 T7 을 못 읽었다. macOS 개인정보 보호(TCC)가 실행 파일별로
외장 볼륨 접근을 허가하기 때문이다. 운영·API 서비스가 되는 이유는 Python.app 이 이미 허가를 받아서다.
**서비스로 돌릴 것은 서비스 컨텍스트에서 시험한다** — `launchctl submit` 으로 한 번 돌려 보면 된다.
그리고 같은 상태 파일에 수동 시험과 서비스가 둘 다 쓰면, 수동 결과를 서비스 결과로 읽는다 —
**타임스탬프가 바뀌었는지, 서비스 전용 로그에 찍혔는지**로 확인한다.

### G-6. 문서에 적은 명령은 실행해 본 명령이어야 한다

2026-09-22: HANDOFF 에 적어 둔 `.venv/bin/python scripts/backfill_kma.py …` 가 import 실패로 즉시 끝났다.
`scripts/` 아래 파일을 직접 실행하면 루트가 `sys.path` 에 없다. 문법·인자만 검사하고 실제로 돌려 보지 않은 명령이었다.
