# Phase 26 — 세계 해상 항로망 자동 계산

작성일: 2026-09-12 UTC. 사용자 요청: 세계 항구 추가 이후 제안한 다음 단계 진행.

## 1. 구현 범위

항구 두 곳을 선택하면 공개 해상 항로망에서 거리 기준 경로 후보를 계산하고,
선택한 경로의 원래 형상을 전 지구 파랑 예보·일정 속력 시뮬레이션에 넘긴다.
이전의 두 항구 대표점을 직접 연결하는 선과 달리 대륙을 돌아가는 경로를 계산한다.
결과의 상태는 `candidate`, 범위는 `network_segment_only`이다.

**항구 대표점에서 항로망 접속점까지는 검증된 입출항 수로가 아니다.**
그 간격은 별도 표시하고 해상 구간 거리·시간·연료에서 제외한다.
화면의 시작 시각은 항만 출항 시각이 아니라 외해 구간 시작 시각으로 해석한다.
항만 도착 마감 충족 판정은 `not_applicable`로 반환한다.

산업용 항해 적합성·실선 항차 검증·현재 통항 가능성을 승인하는 단계가 아니다.
Phase 24의 전 지구 예보 정확도 검증 게이트도 이 변경으로 통과 처리하지 않는다.

## 3. 원래 형상과 날짜변경선

간선 `id`는 원본 `fid`, `coordinates`는 원본 LineString의 모든 꼭짓점이다.
간선 끝점만 이어 곡선·해안 우회 지점을 생략하지 않는다.
계산 후에도 사용한 원본 간선 ID와 전체 웨이포인트를 계획 파일에 보존한다.

날짜변경선의 같은 위도에 있는 `+180/-180` 끝점 쌍 12개만 같은 정점으로 표현한다.
상위 Java 구현은 일부 위도가 다른 반대편 근접 정점도 0비용으로 연결하지만,
그 방식은 위치 차이를 없애므로 사용하지 않는다. 미일치 끝점은 매니페스트에 기록한다.
그래도 이번 원본 그래프는 한 연결 성분으로 남는다.

원본 간선 29787의 내부 경도 180.7535/180.212 두 점은 동등한 음의 경도로만 정규화했다.
원본 값과 정규화 값은 `wrapped_longitude_vertices`에 보존한다.
날짜변경선에서 같은 실제 위치가 연속해 생기는 0거리 구간은 중복 처리한다.

## 4. 거리와 육지 검사

거리는 GeographicLib의 WGS84 타원체 측지선으로 원본의 모든 인접 꼭짓점 사이를 합산한다.
사용한 측지선 방법은 Karney (2013), DOI `10.1007/s00190-012-0578-z`에 따른다.
단위 변환은 1 nautical mile = 1,852 m이다.

육지는 기존 **Natural Earth v5.1.1, 1:10 million** 자료를 사용한다.
각 측지선을 최대 2 nm 간격으로 세분화하고 날짜변경선에서 분할한 뒤,
근사 폴리라인 전체와 육지 다각형의 `intersects`를 검사한다.
표본 지점 사이에 있는 섬도 선과 다각형이 만나면 거부한다.
다만 2 nm 사이 측지선의 폴리라인 근사와 해안선 자료 자체의 정밀도 한계는 남는다.
해도에만 표현되는 작은 섬·암초·방파제·수로 또는 수심 여유를 확인한 것은 아니다.

이번 고정 자료에서 육지 검사에 통과한 간선은 **70,173 / 72,478개**였다.
이 수는 항행 가능한 간선의 인증 수가 아니다. 수심·흘수·통항 규정은 검사하지 않았다.
그래프 SHA, 해안선 4개 구성 파일의 SHA, 검사 정책 버전을 캐시 키에 넣는다.
비용·통과 여부 캐시 자체도 SHA를 확인하며 맞지 않으면 재계산한다.
완성된 경로는 다시 전체 육지 교차와 누적 거리 정합성을 검사한다.

## 5. 경로 탐색과 통로 제약

유한한 양의 WGS84 간선 거리로 Dijkstra 최단 경로를 계산한다.
이는 이번 고정 그래프에서의 거리 최소화이며 연료·시간·파랑·해류 최적화가 아니다.
경로가 없거나 같은 접속점으로 모이면 오류를 반환한다. 직선 대체 경로를 만들지 않는다.
해안선 자료가 없거나 무결성이 깨졌을 때도 계산을 거부한다.

| 제약 | 원본 `pass` 값 |
|---|---|
| 항상 제외하는 운하 | `suez`, `panama`, `kiel`, `corinth` |
| 항상 제외하는 극지 통로 | `northwest`, `northeast` |
| 사용자가 추가 제외할 수 있는 해협 | `malacca`, `gibraltar`, `babelmandeb`, `dover`, `bering`, `magellan` |

항상 제외는 이 프로그램의 보수적인 계산 정책이며 해당 통로가 현재 폐쇄됐다는 진술이 아니다.
항만 접근점·운하 수로·실시간 운영 조건을 아직 확보하지 못했기 때문에 제외한다.
남은 해협을 경로가 지난다는 사실도 현재 통항 가능성이나 허가를 확인한 것으로 해석하지 않는다.

## 6. 항구 연결의 범위

항구 ID는 Phase 25 카탈로그의 원천 항목을 사용한다.
좌표가 없거나 원천 좌표가 불일치하는 항구, 동일한 출발·도착항은 API에서 거부한다.
사용 가능한 간선이 있는 정점 중 WGS84 거리로 가장 가까운 정점을 선택한다.
최단 접속 간격이 100 nm를 넘으면 이 네트워크의 연결 한도 초과로 거부한다.

이 접속 간격은 **reference_gap_not_navigated**이다.
가장 가까운 점이 반도·방파제의 입항 가능한 쪽에 있는지, 항구에서 그곳까지
수로가 이어지는지는 확인하지 않았다. 간격이 짧거나 0에 가까워도 검증된 입출항 수로가 아니다.
UI는 항구 대표점과 접속점을 구별하며 미검증 간격을 별도 표시한다.

미국 서부 후보 `USLGB`(Long Beach), `USOAK`(Oakland), `USSEA`(Seattle)는
이번 카탈로그에서 좌표가 있고 원천 불일치가 없어 항구 입력 검사를 통과했다.
이는 각 항구의 접속 경로나 수로를 검증한 결과가 아니다.
`USLAX`(Los Angeles)는 UN/LOCODE와 WPI 대표점에 33.276 km 차이가 있어
현재 자동 계산 입력에서 거부한다. 임의로 어느 좌표가 옳다고 선택하지 않는다.

## 7. 저장 계획·항로 분석·화면

`POST /v1/routing/plan`은 항구 ID 두 개와 선택적 `avoid_passages`를 받는다.
`sea-route-1.0` 응답에 좌표·사용 간선·항구 원천·항로망 판본·해안선 해시·제약을 저장한다.
정규 JSON 전체의 SHA-256이 `plan_id`이며 `data/routing/plans/<plan_id>.json`에 저장한다.
생성 시각도 해시에 포함되므로 같은 조건을 다시 계산하면 새 계획 ID가 생길 수 있다.
해시는 같은 조건의 중복 제거 식별자가 아니라 저장한 계획 내용의 무결성 근거다.

`GET /v1/routing/meta`는 원천 판본과 강제 제외를 제공한다.
`GET /v1/routing/plans/{plan_id}`는 저장 파일의 SHA를 확인한 뒤 반환한다.
`POST /v1/voyage/analyze`에 `route_plan_id`를 넣으면 서버는 다음을 다시 확인한다.

1. 전 지구 예보 원천인지, 저장 계획이 존재하며 변조되지 않았는지.
2. 입력 웨이포인트가 저장된 원형 좌표와 허용오차 `1e-8`도 이내로 같은지.
3. 항만 `port_id`를 외해 웨이포인트에 임의 혼합하지 않았는지.
4. 강제 제외·육지 검사 정책과 해안선 파일의 SHA가 유지됐는지.
5. 경로 전체가 육지 재검사와 저장 거리 정합성을 통과하는지.

통과한 자동 경로의 분석 응답은 `voyage-1.4`, `scope=network_segment_only`이며
`route_plan`에 원천 근거를 포함한다. 항만 도착 마감은 평가하지 않는다.
예보 지평 이후의 파랑은 기존 규약대로 결측으로 남으며 전 항차에 예보가 있다는 인상을 주지 않는다.

기존 수동 입력은 **2–20개 지점** 한도를 유지한다.
자동 경로는 전체 원형을 보존하기 위해 검증된 계획 ID와 함께 **최대 5,000개 지점**을 허용한다.
20점 한도에 맞추려고 단순화하여 곶·섬을 가로지르는 선을 만들지 않는다.
자동 경로의 좌표 편집과 지도 지점 추가는 잠그며 수동 전환하면 이전 수동 입력을 복구한다.
항구 검색·회피 조건·예보 원천을 바꿀 때 이전 계산 응답은 폐기하여 다른 조건의 경로를 덮어쓰지 않는다.
저장한 자동 경로 분석 JSON을 불러올 때에도 계획 ID로 서버의 원본 계획을 읽고
파일 속 좌표와 대조한다. 20점 수동 파서에 자동 경로를 억지로 통과시키지 않는다.
브라우저 저장 복원과 파일 복원 모두 입력 변경 중 도착한 과거 응답을 무시한다.

보고서에 세 성공 계획의 `plan_id`와 실제 요청 소요 시간도 보존했다.
이 단일 실행의 소요 시간은 동시 사용자 부하 시험이나 처리량 보증이 아니다.
수에즈 등 강제 제외 통로를 배제한 그래프 결과이며 실제 운항 항차의 최단 거리라고 주장하지 않는다.
접속 간격은 거리에서 제외했다. 이 값은 소프트웨어·자료의 재현 사례이며
독립 선박 항적과 비교한 정확도 성적이 아니다.

프로젝트 루트에서 원본 표현을 재현한다.

```sh
.venv/bin/python data/static/routing/build_network.py --offline
```

운영 API가 실행 중이면 다음 요청으로 항구 선택부터 확인한다.
초기 해안선 검사 캐시가 없으면 첫 요청에 준비 시간이 필요하다.

```sh
curl -sS http://127.0.0.1:8811/v1/routing/meta
curl -sS http://127.0.0.1:8811/v1/routing/plan \
  -H 'Content-Type: application/json' \
  -d '{"departure_port_id":"unlocode:KRPUS","arrival_port_id":"unlocode:SGSIN","avoid_passages":[]}'
```

응답의 `plan_id`로 저장 계획을 조회하고, 반환된 **모든** `waypoints`와 그 ID를
전 지구 항로 분석 요청에 전달한다. 임의로 두 끝점만 남기면 저장 형상 대조에서 거부돼야 한다.
부산–싱가포르와 Rotterdam–Shanghai를 브라우저에서 항구 검색→계산→파랑 분석까지 확인한다.

회귀 검사 명령과 확인 대상은 다음과 같다. 전체 테스트 수치는 완료 보고 시 별도로 기록한다.

```sh
.venv/bin/python -m pytest -q tests/unit/test_routing_review.py
node --experimental-default-type=module --test tests/web/routing*.test.mjs
```

- 얇은 섬을 사이에 둔 구간, 날짜변경선 근처 육지, 고위도 측지선의 육지 교차 검출.
- 강제·선택 제외 통로, 끊긴 그래프, 동일 접속점의 오류 유지와 직선 대체 금지.
- 날짜변경선 중복 점의 0거리 처리, 원래 꼭짓점 유지, 왕복 거리 일관성.

## 9. 남은 해운 게이트

검증된 항만 입출항 접근점·공식 수로·수심·선박 흘수 및 통항 조건이 필요하다.

거리뿐 아니라 접속 오류·부적절한 해협·미세 육지·허용 안전 여유를 함께 평가해야 한다.
