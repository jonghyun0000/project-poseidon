## 2. 개편 결과

**정직성 장치 (이 프로젝트의 정체성)**
- 사이클 신선도 3단계(`realtime` / `recent` / `historical`) — 27.5 h 경과 시 적색 **"아카이브 — 실시간 아님"**
- 엔진 출처 상시 표시: `spectral_wave-L1-0.25deg · advection=uno2 · gse=none`
- AI 보정: **"미적용 — 물리 원값. 보정기 미배포(data/models/corr-hs.json 없음)"**
- 오프라인 LSO-CV(+9.3%)를 표시하되 **"교차검증 결과이며 배포 성적이 아니다"** 명시
- 파고대별 희박 구간에 `희박` 배지 + "관측 최대 3.2 m — 이보다 높은 파고는 **검증 불가**.
  해운 판단에서 중요한 고파랑 구간이 바로 검증되지 않은 구간"
- L1 대 L2: **"L2가 L1보다 RMSE 4.4% 나쁘다. 고해상도가 곧 고정확도가 아니다"**
- 부산 패널: 예보 사이클과 조석 기준 시각의 차이를 경고

**신규 기능**
- 검증 성적 패널 5탭(리드별·관측소별·파고대별·L1대L2·방법), 95% CI 부트스트랩 명시
- 부이 마커 클릭 → 사이클별 예보 스파게티 플롯 + 관측 시계열
- 지점 예보에 **적용가능성 배지**(검증 범위 내/밖) + 최근접 검증 관측소 거리·성적 + 물리 원값 열
- 사이클 선택 UI(15개, 예보 없는 사이클은 클릭 차단) + 시간 애니메이션 재생
- L2 도메인 점선 경계 표시

## 3. 검증에서 잡힌 신규 결함과 수정

**[심각] `/v1/forecast/point`의 육지 오염 — 이 프로젝트에서 네 번째 반복**
서빙 경로가 `ds.hs.interp()` 순수 겹선형을 써서 육지 셀 hs=0을 섞었다. 검증 파이프라인은
`collocate.sea_normalized`를 쓰는데 서빙만 달랐다. 실측(33.152N 129.242E, land_frac=0.38):
**0.142 m → 0.228 m (+60%)**. 도메인 23,113점 중 4.1%가 육지 혼입, land_frac>0.3에서 −57.9%.
→ 서빙도 검증과 **동일 함수**를 쓰도록 통일하고 응답에 `land_frac`·`interp` 노출.

기타 수정: `_wave_forecast` 캐시에 zarr mtime 무효화 키 추가(같은 사이클 재실행 시 옛 배열
서빙 방지), CI null 무가드 7곳(표본 부족 시 패널 전체 렌더 중단) 가드, 희박 배지 무력화 복구
(`(r.sparse ? '' : '')` 양쪽 빈 문자열), 리드 0 h 설명을 **규명된 원인**으로 교체.

## 4. 리드 0 h 이상의 규명 (이번 작업의 부산물)

| 리드 | 자체 RMSE (bias) | GFS-Wave RMSE (bias) |
|---|---|---|
| 0 h | 0.227 (−0.108) | 0.214 (−0.096) |
| 6 h | **0.173** (−0.050) | 0.213 (−0.092) |
| 24 h | **0.190** (−0.013) | 0.248 (−0.098) |

리드 0에서 자체↔GFS-Wave **상관 0.9939, 차이 중앙값 0.0000 m** — 초기장 재구성은 정확하다.
즉 리드 0의 큰 오차는 우리 결함이 아니라 **입력(GFS-Wave)의 품질을 그대로 물려받은 것**이고,
자체 물리가 6 h부터 앞질러 24 h에는 0.190 대 0.248로 벌린다. bias도 −0.108 → −0.013으로
자기 교정하는 반면 GFS-Wave는 −0.09대에 정체한다.
→ **관측 동화(EnKF/OI)로 직접 공략 가능한 항목**이며, 다음 단계의 근거가 된다.

## 5. 남은 과제 (미수정, 기록)
