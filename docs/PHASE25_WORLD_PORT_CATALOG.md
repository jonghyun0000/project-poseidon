# Phase 25 — 세계 항구·항만 위치 카탈로그

기준일: 2026-09-12. 사용자 요청: 세계 항구를 찾아 프로그램에 넣고 해운 시뮬레이션에 연결한다.

## 구현 범위

`/console?view=ports&source=global`에 세계 항구 메뉴를 추가했다. 국가·지역 필터,
이름/별칭/UN·WPI 식별자 검색, 페이지 이동, 지도 군집과 개별 위치 선택, 원천별 등록 근거를 제공한다.
항만 검색과 목록 조회는 로컬 카탈로그에서 동작한다. 배경 지도는 OpenStreetMap을 사용한다.
지도는 선택 국가 전체의 좌표 보유 항목이고 목록에는 검색어가 적용된다.
좌표가 없는 항목도 검색 가능하지만 지도 표시와 항로 추가를 비활성화한다.

출발항은 첫 웨이포인트를, 도착항은 마지막 웨이포인트를 대체하고 경유항은 도착점 앞에 삽입한다.
기존 중간 지점을 보존하며 자동 해상 경로를 만들지 않는다. 입력은 2–20개 지점이어야 분석 가능하다.
항구 좌표를 수정하면 해당 항만 식별자 연결을 제거한다. 동일 좌표의 별도 시설 및 왕복 항로는
웨이포인트별 식별자로 구분하며, 좌표만으로 시설의 정체를 추측하지 않는다.

## 원천과 수록 범위의 해석

- [UNECE UN/LOCODE](https://unlocode.unece.org/): 공식 2025-1 판본의 항만 기능 등록 위치.
  UN/LOCODE는 무역·운송 **위치**를 식별한다. 기능 1은 위치 내 항만 존재를 뜻하며 위치 코드 전체가
  단일 항만이나 단일 터미널이라는 뜻은 아니다. 판본의 좌표는 위치를 대표하는 분 단위 참고값이다.
  [Recommendation 16](https://unlocode.unece.org/recommendation16/),
  [좌표 필드 설명](https://unlocode.unece.org/docs/data-attributes/).
- [NGA World Port Index](https://msi.nga.mil/Publications/WPI): 항만·부두·터미널 등 시설 자료.
  공식 [WPI Viewer](https://fgmod.nga.mil/apps/WPI-Viewer)가 사용하는
  [FeatureServer](https://fgmod.nga.mil/nauticalpubs-feature/rest/services/WPI/WPI_Viewer/FeatureServer/0)의
  전체 레코드 수와 페이지 수신 결과를 대조한다.

집계 단위는 항만 위치·시설 레코드다. 서로 다른 원천의 위치와 시설 관계가 완전히 정리된
물리 항구 고유 수가 아니며, 세계의 모든 소규모 항구·마리나·접안시설을 빠짐없이 확보했다는 주장도 아니다.
같은 UN/LOCODE에 속한 여러 WPI 시설을 각각 보존한다. 동일 WPI 번호의 실제 충돌도 덮어쓰지 않는다.

상하이·상하이항 검색 별칭을 해당 공식 항만 코드에 연결했다. IATA와 관행 코드로 항만을 추정하지 않는다.
한글 별칭은 검색 편의용 수작업 목록이며 공식 원천의 정식 한국어 명칭으로 주장하지 않는다.
국가명은 화면에서 한국어로 표시하되 상세에 원천 표기를 함께 남긴다.

## 항로 계산과 출처 보존

`Waypoint.port_id`는 선택형이고 기존 좌표 전용 요청은 그대로 지원한다.
서버가 한 카탈로그 스냅샷에서 선택한 항구를 조회해 좌표와 식별자의 일치 여부를 검사한다.
알 수 없는 ID, 좌표 없음 또는 기준점과 좌표 불일치는 422이고 카탈로그를 읽지 못하면 503이다.
좌표를 임의로 바다 쪽으로 옮기지 않는다.

항만 연결이 있는 분석 결과는 `voyage-1.3`이며 `port_references`에 웨이포인트 번호,
정식 이름, UN/WPI 코드, 좌표 원천, 원천 레코드, 카탈로그 ID·SHA-256을 보존한다.
좌표 충돌·코드 상태와 원본 파일별 SHA-256을 포함한 원천 스냅샷도 함께 저장한다.
분석 JSON은 전체 근거를, CSV는 웨이포인트별 항만 ID와 카탈로그 SHA-256을 포함한다.
클라이언트가 보내는 이름·출처는 감사 근거로 신뢰하지 않고 서버 원천으로 확정한다.

**항구 대표점은 항만 입구·도선점·선석·항행 가능 웨이포인트가 아니다.**
기존 Natural Earth 육지 표본 검사를 유지한다. 육지 통과 시 분석을 무효 항로로 표시하고 재생·연료 판정에
사용하지 않는 기존 정책이 유지된다. 미검출도 항해 가능성 인증이 아니다.
실제 수로·항로폭·수심·흘수·조석 창·입출항 제한·교통관제·정박 및 항만 혼잡은 이 단계의 계산에 없다.

## API

| 경로 | 내용 |
|---|---|
| `GET /v1/ports/meta` | 등록 범위·좌표 보유·국가 목록·원천 판본·검사 내역 |
| `GET /v1/ports?q=&country=KR&limit=30&offset=0` | 검색 결과와 페이지 정보; 전체 국가는 country 생략 |
| `GET /v1/ports/geojson` | 좌표가 있는 항목의 군집 지도용 자료; 선택형 country |
| `GET /v1/ports/{port_id}` | 개별 항만 위치·시설의 좌표와 출처 |
| `POST /v1/voyage/analyze` | 선택형 waypoints[].port_id 검증 및 분석 근거 추가 |

## 남은 단계

다음 실무 단계는 항구 대표점과 실제 해상 접근점을 구분한 항만 접근 자료, 항행 제약을 반영하는
해상 항로 그래프, 수에즈·파나마 등 통항 조건과 선박 제원을 연결하는 것이다.
자료 확보·검증 없이 두 항구 사이의 직선을 추천 항로로 승격하지 않는다.
전 지구 파랑 정확도에 남은 계절·고파랑·남극해 게이트는 Phase 24의 별도 과제다.

## 운영과 재현

```bash
.venv/bin/python -m poseidon.ports.build --offline
.venv/bin/python -m poseidon.ports.build --download
```

`--offline`은 확보한 원본과 SHA-256을 확인하고 동일 내용의 카탈로그를 재생성한다.
실제 재처리에서 위 카탈로그 SHA-256과 전체·좌표 집계가 일치했다.
`--download`는 공식 원천의 새 스냅샷을 받아 검사를 통과한 뒤 공개한다. UN 판본은 명시적으로 2025-1에 고정했다.
새 정식 판본 전환은 스키마·기능·상태 코드 확인 후 별도 코드 변경이 필요하다.
실패한 다운로드·원본 해시 불일치·페이지 누락·중복 객체 ID는 기존 카탈로그를 대체하지 않는다.

저장 위치는 `data/static/ports/`의 원본 `raw/`, 불변 카탈로그 `catalogs/`,
불변 전체 판본 메타데이터 `manifests/`, 현재 공개 메타데이터 `manifest.json`이다.
`reports/world-ports-catalog.json`은 이번 등록 범위 복사본이며
`world-ports-voyage-request.json`과 `world-ports-voyage-result.json`은 실제 API 왕복 검증 자료다.
부산–울산 대표점 두 개 연결(27.642 nm)은 육지 통과가 검출되어 `invalid_route`다.
이는 항만 선택 기능의 검증이며 실제 입출항 추천 항로가 아니다.

API 서비스만 갱신했다. 이 작업 중 확인한 운영 프로세스 PID 805와 동결된 물리 엔진은 유지했다.
과거 Phase 24 문서의 PID 90164는 당시 기록이며 현재 프로세스 번호로 재사용하지 않는다.
