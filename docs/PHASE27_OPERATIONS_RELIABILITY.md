**caffeinate 가 막지 못하는 것**: 덮개 닫힘, 배터리 상태의 시스템 절전, 재부팅, T7 분리.
상시 운영에는 **전원 연결 + 덮개 열림**(또는 외부 모니터 클램셸)이 필요하다. 이것은 코드로 해결되지 않는다.

### 감시 (`scripts/health_check.py`)

"프로세스는 살아 있지만 일을 못 하는" 상태를 잡는다. 하나라도 걸리면 macOS 알림 + `~/Library/Application Support/Poseidon/health.json`.

1. 프로젝트 폴더(T7)가 보이는가
2. 운영 루프 프로세스가 있는가
3. 최신 발행 예보가 18시간보다 오래됐는가 (정상 약 5.5~11.5 h)
4. 발행 후 48시간 지난 최근 사이클(2~4개)의 채점이 전부 0건인가
5. T7 여유 20 GB 미만인가

같은 경보는 6시간에 한 번만 알린다. 경보 내용이 바뀌면 바로 알린다.

**검증**: 백필 **전** 카탈로그 사본에 돌리면 "채점 0건 2사이클 연속" 경보가 난다. 지금 카탈로그에서는 나지 않는다.
이번 12일 공백을 이 장치가 있었다면 잡았다.

**설계가 두 번 바뀌었다 — 둘 다 기록한다.**
1. 처음엔 채점 판정에 "최근 4사이클"을 요구했다. 루프가 멈추면 사이클 수 자체가 적어 **바로 그 상황을 놓친다**
   (착수 시점에 해당 창의 사이클이 2개뿐이었다). 2개 이상으로 낮췄다
2. 처음엔 zsh + `/usr/bin/sqlite3` 로 짰다. launchd 에서 실행하자 **macOS 개인정보 보호(TCC)가 외장 볼륨 접근을 막았다**
   (`ls: Operation not permitted`, `sqlite3: authorization denied`). 대화형 셸에서는 멀쩡해서 수동 시험으로는 드러나지 않았다.
   이미 권한을 받은 Python.app 을 쓰도록 **내장 디스크의 프레임워크 파이썬 + 표준 라이브러리**로 다시 짰다.
   zsh 에 전체 디스크 접근을 주는 방법은 보안 설정 변경이라 택하지 않았다

그 과정에서 셸 판이 조회 실패를 "발행된 예보가 없다"로 보고했다 — 원인은 권한인데 예보 문제로 읽혔다.
지금은 조회 실패를 별도 경보로 분리한다.

## 3. 최신 우선 (단점 3)

`poseidon/scheduler/operational.py`

- `forecast_order()` — 예보는 **최신 사이클부터**. 루프는 반복마다 예보를 하나만 성공시키고 원천을 다시 조회하므로,
  백로그 처리 중 새 사이클이 도착하면 다음 반복에서 맨 앞에 선다
- `secure_inputs()` — 입력(강제장·경계)이 없는 사이클을 **오래된 것부터 전부** 먼저 받는다.
  수집은 사이클당 약 40초, 예보는 25~46분이다. NOMADS 10일 보관 창 가장자리부터 받아 두면
  예보를 최신 순으로 해도 입력이 사라지지 않는다. 받은 입력은 기한 없이 오프라인 예보할 수 있다

**테스트** (`tests/unit/test_operational.py`): 신규 5건 + 기존 1건 기대값 갱신(최신 먼저, 실패 격리 의도는 유지).
신규·갱신 6건은 **옛 코드에서 모두 실패**하고 새 코드에서 통과함을 확인했다 — 회귀를 실제로 잡는 테스트다.
