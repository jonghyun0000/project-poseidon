## 0. PHASE28 의 분류 정정 — 결함은 둘이었다

PHASE28 §1 은 리드 0 영값 셀을 "스텐실 오염 26% / GFS-Wave 가 육지로 보는 마스크 불일치 74%"로 나눴다. **틀렸다.**
그 분류는 최근접 보간(`interp(method="nearest")`)의 NaN 을 "원천 육지"로 읽었는데, 최근접 보간은 **원천 범위 밖**에서도 NaN 을 낸다.

원천 경계 자료(boundary zarr)의 위도 범위는 **15.0~50.0°N** 이다(`core/types.py` `EAST_ASIA`). 예보 도메인은 **12.5°N** 부터다.
20260920T00 실측, 리드 0 해상 영값 1,287셀:

| 결함 | 셀 | 원인 | 영향 범위 |
|---|---:|---|---|
| **D1 범위** | 906 (12.5~15°N 해상 셀 **전부**) | 수집 범위가 예보 도메인 남단을 덮지 않는다 | 초기장·**바람**·**남쪽 경계** 모두 0. 남쪽 경계 행(12.5°N)은 72시간 내내 0.011 m 를 넘지 않는다 — 남쪽에서 오는 너울이 차단된다 |
| **D2 스텐실** | 381 (15°N 이상) | 겹선형의 가중 0 모서리가 육지 NaN → 0×NaN = NaN → `nan_to_num` 이 0 | 리드 0 (리드 3 h 이후 물리가 채운다). 연안 관측소 3곳 리드 0 편향 −0.56 m (PHASE28 §2 — 그 수치는 유효하다: 3곳 모두 15°N 이상) |

D2 는 방향성이 있다. scipy 는 격자점에 정확히 놓인 점에 대해 아래쪽 구간을 고르므로 가중 0 모서리가 **남쪽** 이웃이고,
원천 경도가 4e-6° 어긋나 **서쪽** 이웃이 가중 1.6e-5 로 들어간다. 그래서 육지 격자점의 북쪽·동쪽·북동쪽 해상 셀이 오염된다.

**이번 실험은 D2 만 다룬다.** D1 은 수집 범위를 바꿔야 하고(바람·경계·초기장이 함께 바뀐다), 과거 사이클은 원천이 사라져 재현할 수 없다. §5 에 다음 단계로 등록한다.

## 1. 후보와 불변식 — 결과 전 확정

`poseidon/scheduler/wave_inputs.py` `grid_wave_fields(ds, lats, lons, mode)`. 초기장과 매시 경계 갱신에 같은 함수를 쓴다.
자기검증(GFS-Wave 대비 로그 지표)은 기존 방식 그대로 둔다.

| 모드 | 동작 |
|---|---|
| `none` | 기존 방식 (운영 기본값, 비트 동일) |
| `seanorm` | **기존 보간값이 NaN 인 셀만**, 유한 모서리 가중을 다시 정규화한 겹선형. 유한 가중 합 < 0.05(`collocate.MIN_SEA_WEIGHT` 와 같은 값)면 채우지 않는다 — 가중이 거의 0 인 먼 모서리로 채우는 것은 외삽이다 |
| `seanorm_nn1` | `seanorm` 뒤 남은 NaN 셀을, 그 셀에 가장 가까운 원천 격자점의 **체비셰프 거리 1 이내(8방향)** 유한 격자점 중 가장 가까운 값으로. 등거리 허용치 = 원천 격자 간격의 1/1000(경도 4e-6° 어긋남이 만드는 가짜 거리차 무시). 등거리면 평균 |

PHASE28 §4 의 "최대 1셀(0.25°)"을 위와 같이 해석한다(결과 전 확정). 1셀 한도의 동료심사 근거는 찾지 못했다 `[확인 필요]`.

공통:
- 파향은 원형 평균(단위 벡터). 기존 방식이 dirpw 를 **산술** 겹선형 보간하는 것도 결함이지만(350°·10° → 180°) **이번에 고치지 않는다** — 한 번에 하나(AGENTS.md §6-11). 기록만 한다
- 원천 범위 밖(D1)은 어느 모드도 채우지 않는다
- 산출물 attrs 와 `error_sample.features` 에 `init_fill`·`init_fill_version`(v1) 을 남긴다
- 진단 실행(태그 붙은 실행)은 운영 사이클의 실행 상태를 바꾸지 않는다(이전에는 `RUNNING_L1` 로 바꿨다가 되돌렸다 — 실험이 죽으면 운영 사이클이 발행 목록에서 빠질 수 있었다)

**불변식 검증 (결과 전)**
- 발행 98개 사이클의 초기장 전부에서, 두 후보 모두 **기존 유한 셀의 hs·tp·dir 이 비트 단위로 같다**
- 채움 수(사이클 간 거의 일정): `seanorm` 417~418셀, `seanorm_nn1` 은 추가로 709셀. 범위 밖 1,130셀은 손대지 않음. (육지 셀 포함 수 — 모델 육지 셀은 스펙트럼 단계에서 0 이 된다)
- 기존 방식 진단 실행(`--out-tag p31none`, 20260920T00, 6 h) 이 운영 산출물과 **8변수 전부 비트 동일**(리드 0·3.09·6.02 h), 운영 사이클 상태 `PUBLISHED` 유지
- 기존 방식에서 리드 0 zarr hs 와 `nan_to_num(보간 hs)` 의 최대차 2.6e-7 m(해상 셀) — 리드 0 은 초기장 그 자체다
- 단위 테스트 `tests/unit/test_wave_inputs.py` 10건. **첫 구현이 가중 0 × NaN = NaN 을 그대로 되풀이했고 이 테스트가 잡았다**(채웠다고 센 3셀이 전부 NaN)

## 2. 평가 절차 — 결과 전 확정

**사이클 선택 규칙과 그 경로.** 규칙은 "09-07~09-19 사이 72 h·8변수를 가진 발행 사이클 중, 간격 이상으로 가장 이른 것부터 5개".
관측 창(+72 h)이 기상청 백필 끝(09-22 11Z) 안에 들어가야 한다.
- 00Z 만, 3일 간격 → 3개(09-13~09-18 00Z 는 루프 정지로 없음, 원천 10일 창 밖이라 재생산 불가)
- 모든 시각, 2일 간격 → 4개
- **모든 시각, 36시간 간격 → `20260907T00` `20260908T12` `20260910T00` `20260911T12` `20260918T12`** — 채택

세 번의 조정은 모두 후보 실행 전이다. 36시간 간격이면 인접 사이클의 72시간 창이 겹쳐 같은 기상을 공유한다 → **사이클 군집 부트스트랩 구간은 낙관적이다.**

**실행**: 각 사이클 × 후보, 72 h, `--out-tag p31sn`(seanorm) / `p31nn`(seanorm_nn1).
**대조군**: 운영 산출물(`spectral_wave-L1`). §1 의 비트 동일 확인으로 같은 조건.
**채점**: `collocate_wave(..., write=False)` — `error_sample` 에 쓰지 않는다. hs, `land_frac ≤ 0.05`. 대조군과 후보를 (사이클, 관측소, 유효시각, 리드)로 짝지어 **같은 관측**에 대해 비교한다.
**부트스트랩**: 사이클 군집, 2,000회, `numpy.random.default_rng(20260927)`.

게이트(PHASE28 §4 그대로, 해석 명시):
- **G1** 리드 0, S3(KMA:22520·22513·22106): |편향(후보)| ≤ 0.5 × |편향(기존)| **그리고** 두 편향의 95% 구간이 겹치지 않는다
- **G2** 리드 0, 나머지 관측소: 짝지은 예보 차(후보 − 기존) 평균의 95% 구간이 0 을 포함
- **G3** 리드 ≥ 12 h, 전 관측소: 짝지은 예보 차 평균의 구간과 RMSE 차(후보 − 기존)의 구간이 **둘 다** 0 을 포함
- **G4** scientific 91 통과 + 리드 0 해상 영값 비율 보고(목표치 없음)

**미리 적어 두는 한계**
- G2·G3 의 "구간이 0 을 포함"은 동등성 검정이 아니다. 작지만 일관된 변화가 있으면 효과가 무시할 만해도 실패한다. 등록대로 적용하고 효과 크기를 함께 보고한다. **사후에 허용 오차를 만들지 않는다**
- G1 은 S3 리드 0 표본만 쓴다 — 5사이클이면 수십 건이다
- 게이트 통과는 승급이 아니다. 승급하려면 (1) Astra 가 `/v1/skill` 엔진 태그 혼합 판정에 `init_fill` 을 넣고(분업 §6 요청), (2) 사용자 승인, (3) `ENGINE_FREEZE.md` 갱신이 필요하다

**비게이트 민감도**(`scripts/eval_init_fill.py lead0-all`): 발행 사이클 전체에서 리드 0 을 모델 없이 재구성해(§1 의 리드 0 = 초기장 확인) S3·나머지 편향을 모드별로 낸다. 게이트 판정에는 쓰지 않는다.
